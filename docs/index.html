The control path

Before the tool call.
Not after the incident.

Your agent can retry, crash, loop, or lose context. Mycelium places an auditable boundary before consequential tools. Tracers explain incidents afterward. Mycelium prevents or contains them at execution time.

Fits your stack

Your agent stays yours.

Wrap Python callables directly, enable automatic LangGraph boundaries, or register adapters for a custom runtime.

LangGraphCrewAIPlain Python

Configured guards are enforced only where their boundary or supported adapter is wired. If the ledger cannot claim or complete, a consequential tool fails closed. Read the integration guide →

mycelium.yaml

integrations:
  langgraph:
    enabled: true

loop_guard:
  enabled: true
  missing_run_id_policy: error

completion:
  storage: file
  path: ./mycelium-completion.json
  required:
    - id: charge_customer
mycelium doctor --config mycelium.yamlREAD-ONLY CHECK

What this stops

Prevent the expensive mistake.
Not the wrong answer.

  • Prevent charging an order twice after a timeout.
  • Stop duplicate emails or tickets during redispatch.
  • Refuse destructive calls outside the approved scope.
  • Hard-block an ambiguous payment until reconciliation.
  • Stop runaway loops and premature “done.”

What you can run today

The kernel is open.
Hosted operation is next.

What is shipped is the local runtime. A hosted team control plane is the planned paid surface, not a live subscribe path.

Open source · shipped

Local enforcement and local storage: claim, gate, fail-closed, reconcile, and record. File, SQLite, Redis, or Postgres.

Free hosted · planned

One production workflow with limited evidence retention. Not available yet.

Team · planned

Shared durable storage, longer retention, alerts, visibility, and team access. Price stays experimental until someone pays.
