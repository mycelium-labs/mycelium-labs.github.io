01 / THE FAILURE WINDOW

The dangerous moment is after the tool ran—and before the agent knew.

A worker sends the payment. The process dies before the result is committed. On recovery, orchestration sees an unfinished node and dispatches it again.

The second call is operationally reasonable and commercially wrong.

  1. 01Agent requests a consequential action.
  2. 02External system accepts it.
  3. 03Worker crashes before durable acknowledgement.
  4. 04Retry cannot distinguish “never ran” from “ran, result lost.”

02 / THE CONTROL BOUNDARY

Every retry must earn permission to touch the outside world.

Mycelium claims an action before execution, records the outcome after execution, and refuses to guess when recovery is ambiguous.
INCIDENT REPLAY / SEND PAYMENT

WITHOUT A BOUNDARY

  1. 10:04:11tool.execute()$480 SENT
  2. 10:04:12worker exitsRESULT LOST
  3. 10:04:18node retry$480 SENT AGAIN

WITH MYCELIUM

  1. 10:04:11claim action keyEXECUTE
  2. 10:04:12worker exitsSTATE: UNKNOWN
  3. 10:04:18node retryHARD BLOCK
ALLOWNo prior execution. Run once.
RETURNCompleted earlier. Reuse the result.
POLLStill running. Wait.
REPAIRReconcile with the external system.
HARD BLOCKAuthority is ambiguous. Do not execute.

04 / WHERE IT FITS

Protect actions whose duplicate is a real incident.

FINANCIAL

Charge, refund, transfer

Keep a crash from turning one approved transaction into two.

CUSTOMER COMMS

Send email or SMS

Prevent repeat outreach when a graph resumes or a worker is redispatched.

SYSTEMS

Provision or mutate infra

Make uncertain outcomes enter reconciliation instead of blind re-execution.

BUSINESS OPS

Create tickets or CRM records

Deduplicate by action identity across agents, queues, and restarts.

GOOD FIT

You have consequential tools and retryable execution.

  • Agents run on queues, graphs, or restartable workers.
  • An action has a stable business identity.
  • You need a durable answer to “may this execute?”

NOT THE JOB

Mycelium is not a complete agent platform.

  • It does not replace orchestration, tracing, or evals.
  • It cannot make an inherently unsafe tool safe.
  • It refuses ambiguous re-execution; you still define reconciliation.
